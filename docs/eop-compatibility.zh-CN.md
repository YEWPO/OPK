# EOP 兼容性

[English](eop-compatibility.md)

C++ 读取器参考 [eop2midi 格式说明](https://github.com/emizuki/eop2midi/blob/main/specification.md) 独立实现，不包含或调用 Go 源码。该格式是循环 XOR 混淆的二进制容器，记录实体按键和绝对毫秒时间戳；每条事件并非直接存储标准 MIDI 音高。

| 布局 | 已实现支持 |
| --- | --- |
| v200 | 固定 255 键映射表、1–4 个区块、左右手力度、状态为零的终止标记、外部原始 NUL |
| v201 | 长度前缀的映射层；仅在分段唯一时接受首段为零的变体 |
| v301 | 长度前缀的映射层 |
| 其他版本或有歧义的容器 | 明确报错并拒绝 |

限制：文件最大 64 MiB，展开后最多 1,000,000 条事件，时间线最长 24 小时，每个映射区最多 256 键，最多 32 层映射。单次音频回调到期事件超过 8,192 条时触发过载保护并静音。

导入时验证容器边界、记录长度、有限且单调的时间戳、音符/状态/力度范围、保留字节和按下释放配对。已知 v201/v301 布局末尾有一条非事件记录，按参考布局排除。平行层按音高与手别合并：二者均相同才去重，同音高的不同手别分别保留。EOP 扩展 Set-1 扫描码的第 7 位会转换为 Raw Input E0 的第 8 位表示。导入按键随事件保留供显示；修改现场键位不改变导入音高或手别。

## 实验性的 v201/v301 映射偏移

目前假设每个 28 字节映射区头部的首个小端有符号 32 位整数用于选择音级。将其负值归一化为向上 0–11 个半音：`shift = ((-int64(offset) % 12) + 12) % 12`，最终 `pitch = mapped note + shift`。该规则尚未与 Everyone Piano 完整验证。已提供的本地 v301 样本值为 9，因此映射 C 会提高 3 个半音成为降 E。零和 12 的整数倍不改变音高。其他头部参数（包括可能的八度设置）仍有未解释部分；这不是通用的调号识别。

各映射层分别应用偏移后，按音高与手别合并去重，也覆盖 v201 无前缀首段变体。按下和释放使用相同的最终绝对音高；超出 0–127 时拒绝，不钳位或循环。回放和钢琴高亮使用这些音高，与现场移调独立。原生 `.eopiano.json` 保存绝对音高，不会再次应用偏移。旧版按向下偏移规则保存的原生录制不会自动修改；重新导入原始 EOP 可使用新规则。v200 行为不变。

## 回放配置与调名变化

v201/v301 映射动作 `0x0190` 和 `0x0290` 在每次记录的按下事件上分别提高或降低一个半音的音级，与分配的扫描码无关。重复按下记录分别生效，释放不改变配置。本地 v301 样本约 155.882 秒有两次上行动作，对应用户确认的 Eb → F。音级在 0–11 内循环，与初始偏移假设一致。后续音符使用新偏移；已按住的音符保留原音高直到释放。

导入结果保留带时间戳的配置时间线。首段提供初始音级；v301 头部 +4/+8 和 +12/+16 的字在范围有效时提供各手八度和力度。这些解释基于已提供样本，并非完整格式规范。初始八度用于显示，不再次应用于已为绝对值的映射音高。v201 的八度/力度仍未知；v200 保留现有音符/力度导入，没有配置时间线。多层显示采用首段配置，不表示各层的不同设置。

回放和暂停时，演奏控件只读显示文件配置，未知值明确标注。停止、播放结束或更换文件时恢复现场设置，不将回放配置保存到键位方案。原生版本 1 录制可选包含 `configurations` 数组，字段为 `timeUs`、`transpose`，以及可选的 `leftOctave`、`rightOctave`、`leftVelocity`、`rightVelocity`。旧录制仍可读取，音高继续采用绝对值。

其他非音符控制事件不会被当作音符执行；因语义未验证，会跳过并显示警告，可能影响延音或其他原始效果。引用不存在键位映射的事件会被拒绝，不进行猜测。按下音符力度必须为正；不会从未文档化的零力度推断非零值。

## 左右手设置

v200 保留已有的左右手动作与各手力度。v201/v301 的音符映射采用记录内 `+8` 处的小端 32 位整数表示手别：`1` 为左手，`0` 为右手，其他值保留为 Unknown。此解释已与本地提供的 v301 样本核对；v201 采用相同的记录前缀，并通过包含无前缀首段变体的合成测试覆盖，但该字段尚未与真实 v201 样本核对。

每个映射音符的手别在多层合并、移调、松键配对、进度跳转和重播时保持一致。电脑键盘与钢琴键均使用左手绿色、右手紫色、未知金色，不根据现场键位方案或音域猜测。原生录制沿用现有 `hand` 字段保存手别；此前已保存为未知手别的录制不会自动改写，需重新导入原始 EOP 恢复文件中的设置。

元数据先尝试 UTF-8，再在支持时尝试 GB18030。元数据解码不改变音高或时序解释。

首版只读取 EOP。原生录制使用带版本的 `.eopiano.json`；EOP 导出、EOPM、MusicXML、乐谱排版及截图/PDF 识别不在此导入器范围内。界面语言只影响显示文案，不改变格式、错误代码、配置字段和用户元数据。

## 验证状态

测试构造各支持版本的合成容器、多层映射、左右手设置与未知值、v201 零段变体、v200 力度、错误偏移/事件、截断及 3,000 次确定性单字节变异。UI 测试直接导入合成 EOP 文件，检查播放、暂停、跳转和重播时两种键盘视图的颜色，也覆盖文件手别与现场键位相反的情况。这些验证解析器行为，不能证明覆盖真实 EOP 曲库。

在宣称 Windows 版本完全兼容 EOP 前，应使用本地提供或具有适当许可的真实样本，与 Everyone Piano 对比音符顺序、音高、按键高亮、时序、力度和结束行为。没有再分发许可的第三方音乐不得加入仓库。仍未支持的控制或布局必须在发布说明中可见。

## 力度范围与定位

EOP 各手头部力度采用 0–100%；v301 配置和 v200 映射音符的力度按四舍五入转换为 MIDI 0–127。零表示已知的静音设置；v200 的静音按下仍配对释放，但不产生音符。越界 v301 值保持未知，越界 v200 值被拒绝。单事件力度继续使用 MIDI 语义。原生配置力度也使用 MIDI 值，允许零；现有原生文件不重新解释。

定位回放位置时保留播放/暂停状态，并重建目标处的按住音符、踏板、按键高亮和配置。拖动时预览时间，释放后定位。定位到结尾视为完成；再次播放从头开始。
